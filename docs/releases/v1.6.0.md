# ForgeGuard v1.6.0 - Delegation Intelligence

This release adds a portable decision layer for whether and how authorized workers should be used.

- Reuse explicit approval within the current task/scope; request renewed approval only for delegation beyond it.
- Actively evaluate independent work for time, quality, coverage, or verification benefits; avoid workers when coordination costs dominate.
- Specify objective, scope, expected output, evidence required, and constraints for every worker.
- Keep planning, integration, conflict resolution, final verification, and the final response with the primary agent.
- Resolve instruction priority explicitly and distinguish hard requirements from recommendations.
- Calibrate verification to risk and scope and avoid redundant checks without new evidence or concerns.
- Default depth is 1; workers must not spawn subagents under this policy.

The managed Codex AGENTS block activates these concise rules; full policies ship in the skill references. Existing references remain available.

## Upgrade

Run `forgeguard install --force`, preserving your original client/global options, and start a new coding-agent session. No migration or new CLI flag is required.

The optional runtime preset remains `gpt-5.6-luna` with `xhigh` reasoning. Existing `--subagents`, `--subagent-model`, `--subagent-reasoning`, and `--no-subagent-config` flags are unchanged. ForgeGuard does not change the primary model, mandate delegation, automatically route models, or become a standalone multi-agent runtime.

## Release validation

Run `npm test` and `npm pack --dry-run`. The existing CI matrix runs Node.js 18, 20, and 22 and checks install/status/reinstall/uninstall. Tests validate installed policy references, managed instructions, version consistency, preservation, and runtime defaults. Policy text checks protect the shipped contract; they do not prove model compliance. Exercise the five [delegation scenarios](../../examples/USAGE.md#13-small-task-with-authorization) in the target client when evaluating agent behavior.

Remote CI must pass before release; local test results alone are not evidence of remote CI success.
